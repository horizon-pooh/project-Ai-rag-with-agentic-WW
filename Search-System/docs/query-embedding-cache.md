# แคชเวกเตอร์คำค้น

API เก็บเฉพาะเวกเตอร์คำค้นที่ตรวจแล้วในหน่วยความจำของแต่ละ process หมวดและสินค้าใช้แคชร่วมกันเมื่อข้อความและ profile ตรงกัน ไม่เก็บผลสินค้า ราคา หรือผลตรวจความพร้อมของฐาน

## ขอบเขต

- ค่าเริ่มต้น 128 รายการ งบขนาดที่นับได้ 4 MiB และอายุ 60 วินาที อายุไม่ต่อเมื่ออ่านซ้ำ ลบรายการที่ไม่ได้ใช้ล่าสุดก่อนเมื่อเต็ม
- นับขนาดแบบเผื่อพื้นที่ ไม่ใช่เพดาน RAM ของ Node ทั้ง process
- ขอโมเดลพร้อมกันไม่เกิน 4 งาน คำเดียวกันรอร่วมกันได้ไม่เกิน 64 ผู้เรียก ไม่มีคิวรอไม่จำกัด
- รอโมเดลไม่เกิน 5 วินาที ถ้า provider ไม่ยอมยกเลิก งานยังครอง slot จนจบเพื่อไม่สะสมงานใหม่
- เก็บเฉพาะผลสำเร็จ ตรวจมิติ ค่า finite และ normalization ก่อนเก็บ ไม่เก็บความล้มเหลว

แยก key ด้วย hash ของข้อความตรงตัว รหัสโมเดล profile checksum ไฟล์โมเดล endpoint และข้อมูลยืนยันตัวตน ไม่เก็บข้อความต้นฉบับใน key เวกเตอร์ยังเป็นข้อมูลที่ได้จากคำค้น จึงไม่ควรนำไป log

## ความสดและการขัดข้อง

ทุก request ยังตรวจหมวด ตัวกรอง สถานะ published และความพร้อมของเวกเตอร์จาก SQL ก่อนและหลังเตรียมคำค้น การเปลี่ยนราคา สินค้า หรือ draft จึงไม่ใช้ผลเก่า เวกเตอร์คำค้นเดิมใช้ต่อได้เมื่อ profile ยังตรงและเวกเตอร์สินค้าปรับทันแล้ว

แคชที่ยังตรงใช้ได้แม้โมเดลหยุด เมื่อไม่มีแคชหรือหมดอายุและโมเดลเรียกไม่ได้ จะใช้ keyword พร้อมเหตุผล งานเต็มก็ใช้ keyword ส่วนฐานล่มหรือ SQL ผิดยังคืน `search_unavailable` ไม่คืนผลสำเร็จเก่า

เปลี่ยนไฟล์หรือวิธีสร้างเวกเตอร์ต้องปรับ profile/checksum ในระบบเดิมและสร้างเวกเตอร์ที่ตรงกัน HTTP ไม่ได้ยืนยัน checksum ไฟล์ที่กำลังโหลดแทนผู้ดูแล

## ตั้งค่า

```bash
cp -n .env.query-cache.example .env.query-cache.local
npm run dev:hybrid
```

ไฟล์นี้เป็นตัวเลือก ค่าเริ่มต้นใช้ได้เลย `dev:hybrid` และ `dev:semantic` โหลดให้ หากรันด้วยวิธีอื่นให้โหลด environment เอง ปิดด้วย `SEARCH_QUERY_CACHE_ENABLED=false`

ตัวแปรในไฟล์ตัวอย่างปรับจำนวนรายการ ขนาด อายุ และจำนวนงานพร้อมกันได้ ตัวเลขผิดจะหยุดตั้งค่า ไม่แปลงค่าเงียบ ๆ แคชอยู่ใน API process เท่านั้น คำสั่ง CLI ที่เปิดใหม่แต่ละครั้งไม่ใช้แคชร่วมกับ API

คำเดิมรอบสองอาจมี `product_query_embedding_cached` หรือ `category_query_embedding_cached` เมื่อใช้ผลนั้นจริง งานร่วมใช้รหัสลงท้าย `_shared` หากอ่านแคชแต่ SQL ปฏิเสธความสดจะไม่อ้างว่าใช้เวกเตอร์จัดอันดับแล้ว API ไม่เปิดสถิติหรือเวกเตอร์ผ่าน endpoint

ปิด API แล้วล้างแคช การทดสอบสถิติทำผ่าน dependency ภายใน ไม่เพิ่มข้อมูลใน `/health` เปิดโมเดลและรอ health ก่อน Node ตามวิธีเดิม
