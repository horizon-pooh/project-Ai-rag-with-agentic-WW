# ตารางเวกเตอร์และสิทธิ์ worker

ใช้ตารางเดิม `embedding_models`, `category_embeddings`, `product_embeddings` และเอกสารค้นหา ไม่สร้างตารางเวกเตอร์ซ้ำ คอลัมน์ `vector` ยังไม่ล็อกมิติ โดยตรวจมิติตามโมเดลที่ลงทะเบียน

Migration `0007` เพิ่มข้อมูลติดตามงานสินค้า ได้แก่ เวลา จำนวนครั้ง retry และ lease พร้อมปรับ trigger ตรวจความถูกต้อง

- สถานะ ready ต้องตรงกับโมเดลที่ active มิติ hash และ template ปัจจุบัน
- เวกเตอร์จากโมเดล local ต้องมีข้อมูล configuration และ SHA256 ของไฟล์ พร้อม norm ใกล้ 1
- ข้อความหรือ template เปลี่ยนจะทำให้งานเดิม stale และล้าง lease ส่วนการแก้คำค้นอย่างเดียวไม่บังคับสร้างใหม่
- ข้อมูล configuration ของโมเดลที่มีงานอ้างอิงแล้วเปลี่ยนทับไม่ได้

## บัญชี

`embedding_worker` อยู่ในกลุ่ม `catalog_embedding_worker` อ่านเอกสารสินค้าเฉพาะ published และเขียนได้เฉพาะงานเวกเตอร์ ไม่แก้สินค้า เอกสารต้นทาง หรือโมเดล และไม่ลบตาราง/แก้คีย์

สร้าง role ด้วยผู้ดูแลตาม `embedding-worker-roles.sql` แล้วใช้ `\password embedding_worker` แยกจากคำสั่งอื่น กรอกรหัสใน terminal จนครบก่อนสั่งต่อ

trigger บางตัวใช้สิทธิ์เจ้าของเพื่ออ่านและล็อกแถวที่จำเป็น โดยไม่แจกสิทธิ์แก้ต้นทางให้ worker ส่วน `search_api` ไม่มีสิทธิ์อ่านตารางเวกเตอร์โดยตรง

```bash
npm run db:check-embedding-storage
npm run db:check-embedding-worker
```

การมีตารางพร้อมไม่ได้แปลว่าสร้างเวกเตอร์ครบ ต้องดูจำนวน fresh ตามรุ่นโมเดล การย้อน `0007` จะปฏิเสธหากมีประวัติงานสินค้าที่อาจสูญหาย ให้แก้ด้วย migration ใหม่แทนการลบประวัติ
