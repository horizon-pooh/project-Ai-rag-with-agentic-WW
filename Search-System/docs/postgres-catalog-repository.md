# อ่านสินค้าและรายละเอียด

`createPostgresCatalogRepository(pool)` มี `search(input)` และ `findDetails(article)` ใช้ pool กลางที่ตรวจสิทธิ์แล้ว ไม่เปิด pool ใหม่ต่อคำขอ

การค้นตรวจ JSON เลือกหมวด เรียก SQL แล้วอ่านรายละเอียดเฉพาะ Article ในหน้าผลลัพธ์ ใช้ `REPEATABLE READ READ ONLY` ให้การค้นและข้อมูลสินค้าเป็นชุดเดียวกัน หากเปิดหาหมวดด้วยเวกเตอร์ จะปล่อย connection ก่อนเรียกโมเดลแล้วตรวจใหม่ใน snapshot สุดท้าย

## การอ่านข้อมูล

- รับ Article จำนวนเต็มช่วง 100000–199999 สูงสุด 100 รายการต่อชุด
- อ่านข้อมูลหลัก สเปก และฟีเจอร์แบบรวมชุด ไม่ query ทีละสินค้า
- รายละเอียดรายชิ้นเพิ่มเนื้อหาจาก view `product_content_sections`
- ไม่โหลดสินค้าทั้งฐาน ไม่เปลี่ยนอันดับจาก SQL และไม่ตัดสินค้าที่ข้อมูลผิดออกเงียบ ๆ
- สินค้า draft กับสินค้าที่ไม่มีอยู่คืนผลว่าไม่พบเหมือนกัน

ตัวเลขในฐานอ่านเป็นข้อความก่อนแปลงเป็นค่าที่แสดงได้ รายละเอียดคงค่าทศนิยมต้นฉบับไว้ ข้อมูลไม่ทราบเป็น `null` ส่วนศูนย์และ boolean false ยังคงค่าเดิม

`mapCatalogSearchResponse` แปลงผลภายในให้ตรงสัญญา API ตรวจผลก่อนส่ง และคงข้อจำกัด ตัวกรองที่ใช้ไม่ได้ หน่วยหลัก และข้อความข้อมูลจำลองไว้

```bash
npm run db:check-catalog
```

ฐานผิดพลาดหรือข้อมูลไม่ตรงสัญญาไม่ถูกแปลงเป็นผลค้นว่าง เมื่อจบงานคืน connection เสมอ หาก rollback ไม่สำเร็จให้ทิ้ง connection นั้น
