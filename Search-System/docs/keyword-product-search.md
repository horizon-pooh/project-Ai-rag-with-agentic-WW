# ค้นสินค้าด้วยคำ

`catalog_search.search_products_keyword(text[], jsonb)` รับหมวดระดับสามที่ระบบตรวจแล้วและคำขอ JSON เดิม ใช้ migration `0006` โดยคง `public.search_products` เดิมไว้

SQL ตรวจตัวกรองก่อนจัดอันดับ และอ่านเฉพาะสินค้าที่เผยแพร่ การเรียกใช้ต้องส่งค่าเป็นพารามิเตอร์ ไม่ต่อคำของผู้ใช้เป็น SQL

## ผลค้นหา

- ผลตรงเงื่อนไขที่ตรวจได้มาก่อนผลใกล้เคียงเสมอ รวมถึงเมื่อเรียงราคา
- ผลใกล้เคียงอยู่ในหมวดเดิม พร้อม `unmet_filters` หรือ `unknown_filters`
- ข้อมูลที่ขาดเป็น `actual_value: null` การไม่มีฟีเจอร์บันทึกไว้ไม่แปลว่าสินค้าไม่มีฟีเจอร์นั้นแน่นอน
- เงื่อนไขที่ใช้ไม่ได้ต้องแสดง ไม่อ้างว่าตรงทุกความต้องการ
- `exact.article_id` และ `exact.model` ไม่ผ่อนเพื่อแนะนำรุ่นอื่น

อันดับความเกี่ยวข้องพิจารณาจำนวนข้อที่ไม่ตรง จำนวนข้อที่ไม่ทราบ ระยะห่างเชิงตัวเลข และคะแนนคำค้น ใช้ Article ตัดสินเมื่อเท่ากัน คะแนนนี้ยังไม่ใช่คะแนนเวกเตอร์

นับผล รวมอันดับ และตัดซ้ำก่อนแบ่งหน้า `total_matches` กับ `total_alternatives` เป็นยอดรวม ส่วน `returned_count` เป็นจำนวนในหน้านั้น หน้าที่เกินผลคืน `ok` พร้อมรายการว่าง ไม่ใช่ `no_matches`

```bash
npm run db:check-keyword
```

ผลรองรับสูงสุด 100 รายการต่อหน้า ฐานล่มหรือ query ผิดคืนข้อผิดพลาด ไม่คืนว่าไม่มีสินค้า การเพิ่มดัชนีและวัดประสิทธิภาพเป็นงานแยกจากการตรวจรูปแบบข้อมูล
