# รูปแบบ JSON รุ่น 1

ตรวจด้วย schema และกฎข้ามช่องร่วมกัน ไม่แปลงชนิดข้อมูลหรือแก้ JSON ของผู้เรียกเงียบ ๆ

## คำขอ

- ค่าเริ่มต้น: `version: "1"`, `query: ""`, `filters: {}`, `sort: "relevance"`, `page: 1`, `limit: 20`
- `query` ยาวสูงสุด 200 ตัวอักษร `semantic_query` สูงสุด 2,000
- `limit` อยู่ในช่วง 1–100 และ offset ไม่เกิน 10,000
- ต้องมีคำค้น ความต้องการเชิงความหมาย ตัวกรองที่มีค่า หรือ `exact` อย่างน้อยหนึ่งอย่าง
- ราคาเป็นตัวเลขหรือ null ใช้ THB เท่านั้น ไม่ติดลบ และ min ไม่เกิน max
- สเปกตัวเลขรับ `eq/gte/lte` ข้อความและ boolean รับ `eq` โดยไม่รับหน่วย
- ไม่เดาว่า `"55"` เป็นตัวเลข ค่าจะถูกตรวจตามชนิดสเปกในฐานอีกครั้ง
- รองรับชื่อและรหัสตาม [การส่งรหัส](verified-selector-ids.md) ช่องที่ไม่อยู่ในสัญญาถูกปฏิเสธ

## ผลลัพธ์

สถานะค้นหาคือ `ok`, `no_matches`, `needs_clarification`, `invalid_request`, `constraint_conflict` หรือ `search_unavailable`

ผลตรงอยู่ก่อน alternatives และ Article ไม่ซ้ำ `matches_applied_filters` หมายถึงผ่านเฉพาะเงื่อนไขที่ตรวจได้ หากมี `unapplied_filters` ต้องตั้ง `all_requested_filters_applied: false`

ผลใกล้เคียงต้องบอกข้อที่ไม่ตรงหรือไม่ทราบ ค่าที่ไม่มีเป็น `null` ยอดรวมคำนวณก่อนแบ่งหน้า และหน้าเกินผลอาจว่างทั้งที่ยอดรวมไม่เป็นศูนย์

`request_id` สร้างฝั่งเซิร์ฟเวอร์ ข้อมูลจำลองต้องมี `mock_notice` และไม่ส่งเวกเตอร์หรือข้อมูลลับออกไป ปัจจุบัน `semantic_available: false` หมายถึงการจัดอันดับสินค้ายังไม่ใช้เวกเตอร์ จึงต้องมี warning `semantic_unavailable`

ตัวอย่างใน `examples/tool-search-v1` ใช้อธิบายรูปแบบ ไม่ได้ยืนยันว่ารหัสหรือผลสินค้าตรงกับฐานที่กำลังใช้อยู่
