# ตรวจตัวกรองตามหมวด

จับคู่สเปก แบรนด์ ฟีเจอร์ และหน่วยจากข้อมูลจริงในฐาน หลังจากเลือกหมวดแล้ว ใช้ migration `0004` และอ่านผ่าน client เดียวกับการค้นสินค้า

## กฎหลัก

- หมวดและแบรนด์ใช้ OR สเปกและฟีเจอร์ใช้ AND ภายในแต่ละหมวด
- ตัวเลขรับ `eq`, `gte`, `lte` ข้อความและ boolean รับ `eq`
- ไม่แปลง `"55"` เป็น `55` หรือ `"true"` เป็น `true` โดยเดาเอง
- ความกว้างสินค้าและกล่อง ความจุซักและอบ เป็นคนละสเปก
- รหัสที่ไม่รู้จักไม่ถูกแทนด้วยชื่อหรือ alias
- คำกำกวมให้เลือกเพิ่ม เงื่อนไขที่ใช้ไม่ได้แสดงใน `unapplied_filters` พร้อมตำแหน่ง JSON เดิม
- ค่าไม่มีข้อมูลเป็น `null` ไม่ใช้ `0` หรือ `false` แทน ช่วงค่าขัดกันคืน `constraint_conflict`

ค่าต่ำสุด/สูงสุดใน metadata ใช้อธิบายขอบเขตที่ตั้งไว้ ไม่ได้ยืนยันว่าสินค้าค่าที่อยู่นอกช่วงไม่มีจริง

## หน่วยและความละเอียด

ไม่ส่งหน่วยจะใช้หน่วยหลักของสเปกและระบุว่าเป็นการสมมติ ใช้ชื่อแสดงของหน่วยหลักได้ ส่วนหน่วยอื่นต้องมีกฎแปลงตรงที่เปิดใช้งาน ไม่แปลง kg กับ L

ตัวเลขภายในใช้ PostgreSQL `numeric` และข้อความทศนิยม ค่าเดิมมี epsilon เป็นศูนย์ ค่าที่แปลงหน่วยใช้ `max(abs(n)*1e-12, 1e-12)` ในหน่วยหลัก เพื่อรองรับตัวคูณทศนิยมที่ไม่ลงตัว ไม่ใช่การปัดค่าหรือความคลาดเคลื่อนที่ลูกค้าระบุ

ราคาใช้ THB และยอมรับราคาเป็นศูนย์ เงื่อนไขตัวเลขใช้ช่วง epsilon เดียวกันทั้งตอนตรวจความขัดแย้งและค้นสินค้า

```bash
npm run db:check-filters
```

ใช้ได้สูงสุด 1,907 หมวดระดับสาม และสเปก/แบรนด์/ฟีเจอร์อย่างละ 20 รายการ หากขยายเกินต้องแก้ขีดจำกัดด้วย migration ใหม่
