# รวมอันดับสินค้าด้วย RRF

ใช้ migration `0009` และ `0010` โดยคง keyword เดิมไว้ รับ JSON รุ่น `1` เหมือนเดิม ไม่รับเวกเตอร์จากผู้เรียก API

## การทำงาน

1. เลือกหมวดและตรวจตัวกรองก่อน ตรวจว่าเวกเตอร์สินค้าที่เผยแพร่ในขอบเขตครบและตรงโมเดล
2. ปล่อย connection ฐานแล้วสร้าง query vector จาก `semantic_query` หากไม่ส่งใช้ `query`
3. เปิด snapshot อ่านใหม่ ตรวจความพร้อมซ้ำ แล้วตรวจราคา แบรนด์ สเปก ฟีเจอร์ และ keyword เพื่อแยกผลตรงกับ alternatives
4. จัดอันดับ keyword และ cosine แยกภายในกลุ่มผลตรงและกลุ่ม alternatives แล้วรวมด้วย `1/(60+อันดับคำ) + 1/(60+อันดับเวกเตอร์)`
5. เรียงรวมก่อนแบ่งหน้า ผลตรงมาก่อน alternatives เสมอ สำหรับ alternatives เรียงตามจำนวนข้อที่ไม่ตรง จำนวนข้อที่ไม่ทราบ ความห่างตัวเลขแบบสัดส่วน แล้วจึง RRF ใช้ Article ตัดสินเมื่อเท่ากัน

หากไม่มี `query` จะใช้อันดับเวกเตอร์ทางเดียว เลข 60 เป็นค่าตั้งต้นของสูตร ไม่ได้ยืนยันว่าเหมาะที่สุด คะแนน RRF ไม่ใช่เปอร์เซ็นต์ความมั่นใจ

แม้ไม่มีผลตรงก็ใช้ RRF เรียง alternatives ได้ แต่ยังคง `match_type: alternative` พร้อม `unmet_filters` หรือ `unknown_filters` ไม่เปลี่ยนให้เป็นผลตรงเพื่อเติมรายการ สินค้าที่มีน้อยกว่า limit คืนเท่าที่มี

`semantic_query` ใช้ช่วยจัดอันดับ ไม่ใช่เงื่อนไขบังคับว่าทุกความต้องการในประโยคผ่านแล้ว `matches_applied_filters` ยังหมายถึงผ่านเฉพาะเงื่อนไขที่ตรวจได้

## เปิดใช้

เปิดโมเดลและรอ health ก่อน Node ใช้ profile เดิมใน `.env.embedding.local` กับ `EM0001` ที่ตรวจแล้ว ไม่ลงทะเบียนโมเดลใหม่เพื่อเปิดฟีเจอร์นี้

```bash
cp -n .env.product-hybrid.example .env.product-hybrid.local
npm run dev:hybrid
```

คำสั่งนี้โหลด `.env`, `.env.embedding.local`, `.env.category-semantic.local` และ `.env.product-hybrid.local` ต้องมีไฟล์เหล่านี้ ส่วน `npm run dev` ยังคงทางเดิมตาม environment ที่โหลด

ลองหมวดที่ตรวจแล้วว่าเวกเตอร์ครบ เช่น AP0101 เครื่องซักผ้าฝาหน้า:

```bash
npm run db:check-product-hybrid -- --category-id AP0101 --query "เครื่องซักผ้า" --semantic-query "ซักเสื้อผ้าประจำวัน"
```

คำสั่งตรวจใช้บัญชีอ่านและไม่เขียนข้อมูล แต่เรียกโมเดลเมื่อเวกเตอร์พร้อม ตัวอย่างรหัสอ้างอิงข้อมูลวันที่ 28 ต.ค. 2026 ต้องตรวจ coverage ตามฐานที่ใช้อยู่

## การกลับไปใช้ keyword

- เวกเตอร์ในขอบเขตขาด เก่า โมเดลไม่ตรง หรือ provider ใช้ไม่ได้ จะกลับไป keyword พร้อม warning
- ตรวจความครบทั้งหมวดที่ใช้ค้น ไม่ใช้เฉพาะรายการที่มีเวกเตอร์เพื่อหลีกเลี่ยงผลเอนเอียง
- การเรียงราคา/Article และการค้น Article/รุ่นเจาะจงใช้ทางเดิม ไม่เปลี่ยนรุ่นแทน
- ถ้าโมเดลหรือข้อมูลเปลี่ยนระหว่างเตรียมคำค้น จะตรวจอีกครั้งใน snapshot สุดท้าย
- ฐานล่มหรือ SQL ผิดเป็น `search_unavailable` ไม่ใช่ไม่มีสินค้า

เมื่อรวมอันดับจริงใช้ `semantic_available: true` รวมถึงหน้าที่มีแต่ alternatives ผลยังคง `is_mock`, `mock_notice` และเหตุผลของเงื่อนไขที่ไม่ตรง ไม่ส่งคะแนนภายในหรือเวกเตอร์ผ่าน API รุ่น 1

ฟังก์ชันอ่านคะแนนใหม่ไม่เปิดตารางโมเดลหรือเวกเตอร์ให้ `search_api` ไม่สร้างตาราง ดัชนี หรือข้อมูลเพิ่ม รุ่นปัจจุบันเรียก SQL `search_products_hybrid_v2` การย้อน `0010` ลบเฉพาะรุ่นนี้ โดยคงรุ่น v1 และ keyword ไว้ ต้องปิดฟีเจอร์หรือกลับไปใช้โค้ดรุ่นก่อนพร้อมกับการย้อน

ลองเพดานราคาต่ำเพื่อดูเหตุผลของ alternatives:

```bash
npm run db:check-product-hybrid -- --category-id AP0101 --query "เครื่องซักผ้า" --semantic-query "ซักเสื้อผ้าประจำวัน" --max-price 1
```

`--max-price` เป็นตัวเลขสำหรับคำสั่งตรวจ ส่วน JSON จาก API ยังต้องส่งราคาเป็นชนิด number ตามเดิม
