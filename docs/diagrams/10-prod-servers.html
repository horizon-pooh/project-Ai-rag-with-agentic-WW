10 · DEPLOYMENT · HIGH-LEVEL · LINE_PROD · 28 ต.ค. 2026

ขึ้นใช้งานจริง อะไรอยู่เครื่องไหน

ทุกส่วนของระบบรันบน VM เครื่องเดียว (Docker Compose) ส่วนที่ต้องอยู่เครื่องอื่นมี 3 อย่าง คือ AI gateway (ของผู้ให้บริการ) เครื่องเก็บ backup (ยังไม่เลือก) และตัวเฝ้าระบบจากภายนอก (เสนอ) จุดเสี่ยงคือ Postgres ที่อยู่เครื่องเดียวกับทุกอย่าง ถ้า VM ล่ม ลูกค้าเข้าระบบไม่ได้ทั้งหมด

ส่วนไหนอยู่ที่ไหน

ส่วนอยู่ที่หมายเหตุ
Caddy · API · Worker · WatchdogVMAPI / Worker / Watchdog ใช้ image เดียวกัน
Postgres · MinIOVMข้อมูล คิว replyToken และรูป อยู่ใน volume ของ VM
AI gatewayเครื่องของผู้ให้บริการเราเรียกผ่าน HTTPS ไม่ได้รันเอง
เครื่องเก็บ backupเครื่องอื่น นอก VMยังไม่เลือก รอคำตอบ
ตัวเฝ้าภายนอกเครื่องอื่นเสนอ ยังไม่ได้ทำ
LINEของ LINEwebhook เข้า, push / reply ออก
โดเมน (DNS)ผู้ให้บริการ DNSต้องชี้มาที่ VM ไม่งั้น Caddy ขอใบรับรองไม่ได้

ต้องมีบน VM ก่อนขึ้นจริง

  • Docker Compose v2 (ตาม docker-compose.yml)
  • โดเมนที่ชี้มาที่เครื่อง และเปิดพอร์ต 80 / 443 จากอินเทอร์เน็ต
  • ไฟล์ .env (secret อยู่ที่นี่ที่เดียว)
  • volume 4 ตัวต้องไม่หาย: postgres_data minio_data caddy_data caddy_config
  • พนักงานกดลิงก์ปิดเคสเข้าทาง Caddy เส้นเดียวกับ webhook

ความเสี่ยงก่อนขึ้นจริง

  • VM เครื่องเดียว: ล่มแล้วลูกค้าเข้าไม่ได้ทั้งหมด
  • watchdog อยู่เครื่องเดียวกับที่มันเฝ้า VM ดับทั้งเครื่องแล้วแจ้งเตือนไม่ออก จึงควรมีตัวเฝ้าจากภายนอก
  • backup มีสคริปต์แต่ยังไม่เคยซ้อมกู้ รอคำตอบ
  • ยังไม่เคย docker compose up บนเครื่องจริง
