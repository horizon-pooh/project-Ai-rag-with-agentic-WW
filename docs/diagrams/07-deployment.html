อะไรรันอยู่ตรงไหนบนเครื่อง

ทั้งระบบเป็น Docker Compose บนเครื่องเดียว มีแค่ Caddy ที่เปิดพอร์ตออกอินเทอร์เน็ต api, worker และ watchdog ใช้ image เดียวกันที่ build จากโค้ดนี้ ส่วน Postgres เก็บทั้งข้อมูลและคิวงาน จึงเป็นจุดที่ล่มแล้วหยุดทั้งระบบ และสำรองออกนอกเครื่องทุกคืน

service ใน docker-compose.yml

serviceimage / คำสั่งหมายเหตุ
caddycaddy:2เปิด 80/443 อย่างเดียวของระบบ, route ตาม Caddyfile
migratedbmate:2 upรันครั้งเดียวแล้วจบ (exit 0)
apiuvicorn app.main:create_appexpose 8000 ภายใน, healthcheck /health
workerpython -m app.workerstop_grace_period 30 วิ
watchdogpython -m app.worker.watchdogแจ้งผู้ดูแลเมื่อ worker ตายหมด / คิวค้าง / DB ล่ม
postgrespostgres:16ข้อมูล + คิว + replyToken
miniominio/minioรูปลูกค้า

ลำดับเริ่ม

  1. postgres healthy (pg_isready ผ่าน TCP)
  2. migrate apply migrations/*.sql จบด้วย 0
  3. api, worker เริ่ม (worker ไม่รอ MinIO พร้อม)
  4. caddy ขอใบรับรอง Let's Encrypt แล้วรับ webhook
  5. watchdog เริ่มหลัง postgres (ไม่รอ healthy — ต้องรายงานได้แม้ DB ไม่ขึ้น)

ไม่มีโดเมน: ใช้ Cloudflare quick tunnel ชี้ api:8000 ตรง (ข้าม Caddy) ทดสอบเท่านั้น

ความเสี่ยง / ยังไม่ทำ

  • เครื่องเดียว: postgres ล่ม = ทั้งระบบหยุด (ข้อมูล คิว และ replyToken อยู่ที่เดียว)
  • backup: มีสคริปต์แล้ว (deploy/backup/, cron 03:30) แต่ยังไม่ซ้อมกู้บน VM จริง และยังไม่รู้เครื่องปลายทาง รอคำตอบ
  • minio/minio ไม่ pin เวอร์ชัน
  • ยังไม่เคย docker compose up บนเครื่องจริง
