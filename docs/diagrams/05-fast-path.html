ลูกค้าขอพนักงานระหว่างรอ AI

ทางด่วนเปลี่ยนสถานะเป็น human ทันทีโดยไม่รอคิวของ Worker พอคำตอบ AI มาถึงช้าๆ sendGuard อ่านสถานะล่าสุดเห็น human แล้วทิ้งคำตอบนั้น ลูกค้าจึงไม่ได้การ์ดสินค้าแทรกเข้ามาตอนคุยกับพนักงาน

ปัญหาที่แก้

งานของ user เดียวกันรันทีละงาน (lock ของ procrastinate) ถ้าลูกค้ากด "คุยกับพนักงาน" ระหว่างที่ AI กำลังค้นสินค้า (วัดได้ 22–43 วิ) event นั้นต้องรอคิว

ผลคือ AI ตอบเสร็จ → sendGuard เห็นยังเป็น bot → ส่งการ์ดสินค้าแทรก → แล้วค่อยส่งต่อ

ทางด่วนทำอะไร (ตัดสินแล้ว)

  • webhook เรียกเป็น BackgroundTask ของ FastAPI หลังตอบ 200 ไม่มีคิวแยก (api/fast_path.py)
  • event ที่วิ่งทางนี้: postback talk_to_staff / resume_ai, พิมพ์ "คุยกับ AI" ตรงทั้งข้อความ, ข้อความที่กฎขั้น 5 ส่งต่อทันที (is_fast_path_event)
  • ส่งต่อ: UPDATE … SET status='human' WHERE status='bot' · คืน AI: end_handoff()
  • event ยังเข้าคิวตามปกติ แต่ทางด่วน claim ก่อน worker มาทีหลัง claim ได้ None แล้วข้าม

สถานะ

  • เทสต์ race ผ่านแล้ว: test_escalation_race_* (orchestrator), test_fast_path_* (webhook)
  • ข้อความใหม่ระหว่างรอ AI: ตอนนี้ตอบเรียงทีละข้อความ (ยังไม่รวมคำตอบ)
  • ยังไม่ได้ลองกับ LINE จริง
