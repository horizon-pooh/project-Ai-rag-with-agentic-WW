หนึ่งข้อความเดินผ่านอะไรบ้าง

ทุกข้อความผ่านด่านตามลำดับเดียวกัน กฎในโค้ดตัดสินก่อน AI ทุกครั้ง AI ถูกเรียกเฉพาะเมื่อจำเป็น และไม่ว่าทางไหนก็ต้องจบที่ sendGuard ก่อนถึงลูกค้า

ลำดับขั้นจริงในโค้ด

#ขั้นไฟล์
1–2webhook → คิว procrastinate (lock ต่อ user)api/webhook, worker/tasks
3prepare: user, conversation, redact, รูป, แชทย้อนหลัง 4, consentsteps/prepare
4handoff_checksteps/handoff_check
5rules: ร้องเรียน/ขอคน, FAQ, Vendor 1, ถี่ผิดปกติ, postbacksteps/rules
6–7call_ai → update_statesteps/call_ai, update_state
8validate: SKU/ราคา/ลิงก์, ลบลิงก์แปลกปลอม, สร้างการ์ดsteps/validate
9send (sendGuard)steps/send

sendGuard ทำไมเป็นด่านสุดท้าย

  • อ่านสถานะล่าสุดจาก Postgres ก่อนส่งทุกครั้ง เพราะระหว่างรอ AI (2–43 วิ) ลูกค้าอาจกดขอพนักงาน ครบ 6 ชม. หรือพนักงานกด /close
  • human หรือ kill switch เปิด → ทิ้งคำตอบ + log เหตุผล
  • บันทึกสถานะขาออกก่อนส่ง กันส่งซ้ำตอน retry; push ใช้ X-Line-Retry-Key
  • replyToken เกิน 50 วิ → ใช้ push แทน (นับโควตาข้อความของ OA)

ทางแยกที่ไปหาพนักงาน / ไม่ตอบ

  • TALK_TO_STAFF: ลูกค้ากดปุ่มหรือพิมพ์ขอเอง
  • RULE MATCH: ร้องเรียน / เคลม / ขอคน ไม่เรียก AI (จับแบบ substring "ไม่ต้องคุยกับพนักงาน" ก็ส่งต่อ)
  • AI ERROR: ลองซ้ำแล้วยังล่ม → ข้อความเสี่ยงส่งต่อ ไม่งั้นขอโทษ + ปุ่มคุยกับพนักงาน
  • ถามกลับเกิน CLARIFY_MAX, validate ไม่ผ่านซ้ำ → ส่งต่อ
  • ไม่ตอบ: สถานะ human, keyword Vendor 1, ส่งถี่เกิน (ตอบเตือนครั้งเดียว)
