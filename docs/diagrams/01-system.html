ภาพรวมระบบบน server บริษัท

ระบบเราอยู่ระหว่าง LINE กับ AI gateway บนเครื่องเดียว (Docker Compose) Postgres เก็บทุกอย่าง รวมถึงคิวงาน และ Worker เป็นตัวตัดสินทุกอย่าง AI gateway ค้นสินค้าและตอบเอง เราส่งแชทย้อนหลังที่ redact แล้วเข้าไป แล้วตรวจผลก่อนส่งให้ลูกค้า

ทางเดินของหนึ่งข้อความ

  1. LINE ยิง POST /webhook ผ่าน Caddy (HTTPS)
  2. API ตรวจ signature แล้วบันทึก raw event ลง Postgres เก็บ replyToken แยกในตาราง reply_tokens (50 วิ) ใส่งานลงคิว แล้วตอบ 200
  3. คิวคือ procrastinate บน Postgres ตัวเดียวกัน ไม่มี Redis แล้ว (D-010) งานของ user เดียวกันรันทีละงานด้วย lock
  4. Worker รัน pipeline (ดูภาพ 02) เรียก AI gateway พร้อมแชทย้อนหลัง 4 ข้อความ ได้คำตอบเป็น markdown
  5. ส่งเข้า LINE ผ่าน sendGuard เท่านั้น (reply ถ้า token ยังใช้ได้ ไม่งั้น push)

จุดที่ต้องจำ

  • Worker เป็นที่เดียวที่ตัดสินใจ ข้อความถึงลูกค้าทุกข้อความผ่าน sendGuard
  • fast_path ใน API: "คุยกับพนักงาน" / "คุยกับ AI" เปลี่ยนสถานะทันที ไม่รอคิว (ภาพ 05)
  • watchdog: service แยก เฝ้าว่า worker ยังอยู่ คิวเดิน DB ต่อได้ — ไม่งั้นแจ้งผู้ดูแล (D-012)
  • kill switch: sendGuard อ่านก่อนส่งทุกครั้ง เปิดแล้วระบบไม่ตอบอะไร
  • API ยังเสิร์ฟ /static/no-image.png = รูปแทนบนการ์ดสินค้า (D-013)

ยังไม่รู้

  • แจ้ง call center ผ่านช่องทางไหน — ตอนนี้แค่ log รอคำตอบ
  • AI gateway รับรูปได้ไหม รับพร้อมกันได้กี่งาน รอคำตอบ
  • SMTP / ผู้รับอีเมลแจ้งเตือนของ watchdog รอคำตอบ
  • ยังไม่เคยรันบน Docker จริง (เครื่อง dev ไม่มี Docker)
