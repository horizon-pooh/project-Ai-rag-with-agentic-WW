# การคุยแชทต่อเนื่อง

Softnix เป็น API แบบ stateless คือไม่จำอะไรเลย ทุกครั้งที่ถาม **ระบบเราส่งประวัติแชทล่าสุดไปให้ใหม่** จาก `session:{userId}.history` (ดู `data-model.md`)

```
ส่งให้ Softnix ทุกครั้ง = system prompt + ประวัติ 12 ข้อความล่าสุด + ข้อความใหม่
```

## 5 สถานการณ์

### 1. ถามต่อจากคำตอบเดิม — "ตัวที่ 2 ราคาเท่าไหร่"

- **ปัญหาที่เจอใน MVP:** ตอนตอบสินค้า history เก็บแค่ประโยคเกริ่น (`softnix.extractIntro`) เช่น "ขอแนะนำตู้เย็นดังนี้ครับ" แต่ **ไม่มีรายการสินค้า** (รายการไปอยู่ใน field `products` ซึ่ง `buildMessages` ไม่ได้ส่ง) Softnix จึงไม่รู้ว่า "ตัวที่ 2" คืออะไร
- **production:** ตอนประกอบ history ให้ Softnix ต่อรายการสินค้าแบบย่อท้ายคำตอบของ AI
  ```
  ขอแนะนำตู้เย็น 2 ประตูดังนี้ครับ
  1. ตู้เย็น SAMSUNG RT35 12.3 คิว (SKU 1233787) 14,990 บาท
  2. ตู้เย็น HITACHI R-H200 7.3 คิว (SKU 1107558) 8,990 บาท
  ```
  สั้นพอไม่กินงบ history และ Softnix อ้างถึง "ตัวที่ 2" ได้
- ปุ่ม "ดูรายละเอียด" บนการ์ดไม่ต้องผ่าน AI ใช้ SKU จาก postback ตอบได้ทันที

### 2. พิมพ์เพิ่มระหว่างรอ Softnix — "อยากได้ตู้เย็น" … "งบไม่เกิน 15,000"

- งานเก่าถูกแทน (`activeJobId` เปลี่ยน คำตอบเก่าที่มาทีหลังถูกทิ้ง)
- **งานใหม่ต้องรวมข้อความที่ยังไม่ได้คำตอบทั้งหมด** ไม่ใช่แค่ข้อความล่าสุด ไม่งั้น "งบไม่เกิน 15,000" จะถูกส่งไปโดยไม่รู้ว่าหาอะไร — กฎนี้ใช้แทน `messageBatcher.js` ที่ตัดออก
- ถ้างานเก่า **ยังไม่เริ่ม** → แทนในคิวที่เดิม ลูกค้าไม่เสียคิว
- ถ้างานเก่า **กำลังทำอยู่** → รอให้เสร็จแล้วทิ้ง แล้วเริ่มงานรวม (Softnix หยุดกลางทางไม่ได้) — ลูกค้าจะรอนานขึ้น ต้องบอกตามจริง

### 3. อยู่กับเจ้าหน้าที่ (ESCALATED)

- AI ไม่ตอบ ข้อความลูกค้ายังถูกบันทึกลง history (เจ้าหน้าที่ใช้ดูย้อนหลังได้)
- ลูกค้าพิมพ์ "คุยกับ AI" → กลับมา AI_HANDLING ได้เอง (มีใน MVP แล้ว)
- AI ที่กลับมาเห็นประวัติช่วงที่คุยกับเจ้าหน้าที่ด้วย — ต้องระวังไม่ให้ AI ตอบคำถามที่เจ้าหน้าที่ตอบไปแล้ว (ใส่ข้อความ system "ลูกค้ากลับจากเจ้าหน้าที่" นำหน้า)

### 4. ปิดงานแล้วทักใหม่ (CLOSED → NEW)

- state กลับเป็น NEW แต่ **history ยังอยู่** (เหมือน MVP) AI จึงรู้ว่าเคยคุยอะไร
- ถ้าเงียบเกิน 24 ชม. session หมดอายุ → เริ่มใหม่หมด ไม่มีประวัติ
  - อยากให้จำนานกว่านี้: ปรับ `SESSION_TTL_MS` เช่น 7 วัน — Redis ใช้เพิ่มไม่ถึง 200 MB (ดูหัวข้อค่าใช้จ่ายใน `data-model.md`) แต่ต้องดู PDPA ด้วย

### 5. server restart ระหว่างคุย

- session และคิวอยู่ใน Redis ไม่หาย ลูกค้าคุยต่อได้เหมือนเดิม
- งานที่ Softnix ทำค้างอยู่ตอน restart (`softnix:processing`) → worker เริ่มใหม่ถ้ายังไม่เกิน 5 นาที ไม่งั้นส่งต่อคน

## ยังต้องตัดสินใจ

- จำประวัตินานเท่าไหร่ (24 ชม. หรือนานกว่า)
- ส่งประวัติให้ Softnix กี่ข้อความ (MVP = 12) — ยิ่งมากยิ่งเข้าใจบริบท แต่ Softnix อาจช้าลง
