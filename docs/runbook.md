## อาการ → ทำอะไร

| อาการ | ทำอะไรก่อน |
|---|---|
| ลูกค้าไม่ได้คำตอบเลย / server ล่ม | **เปิด kill switch** ให้ call center รับทั้งหมด แล้วค่อยหาสาเหตุ |
| คิว Softnix ยาวผิดปกติ (ถ้า AI API คือ Softnix) | ดู `/health` → ถ้า Softnix ล่ม เปิด kill switch เฉพาะส่วน AI _(วิธีจะเติมเมื่อมีโค้ด)_ |
| ลูกค้าบอกว่า AI ตอบแทรกเจ้าหน้าที่ | ค้น log ด้วย userId ดูว่า `sendGuard` ตัดสินอะไร |
| Redis ล่ม | _(เติม)_ |
| งานค้าง `pending` นาน | ดู Worker ยังรันไหม, ดูความยาวคิว; งานกวาด `pending` ต้องใส่กลับเข้าคิวเอง _(คำสั่งจะเติม)_ |
| Postgres ล่ม | หยุดตอบดีกว่าตอบผิด (Postgres คือความจริงทั้งหมด); ถ้านานเปิด kill switch _(เติม)_ |
| AI API ล่ม/ช้า | ดู `ai_steps` (latency_ms, error_class); `fallback` ส่งต่อ/ขอโทษ+ปุ่มคุยกับพนักงานอยู่แล้ว; นานผิดปกติแจ้งผู้ให้บริการ AI API |
| ลูกค้าบอกว่า AI ตอบแทรกพนักงาน (แบบใหม่) | ค้น log ด้วย `raw_event_id`/`ai_run_id` ดูการตัดสินของ sendGuard (สถานะที่อ่านได้ตอนส่ง) |

## ซ้อมก่อนขึ้นระบบจริง

- [ ] เปิด kill switch แล้วลูกค้ายังถึง call center
- [ ] restart ระหว่าง Softnix กำลังทำงาน งานไม่หาย
- [ ] ปิด Redis แล้วระบบไม่ตอบผิด (หยุดตอบดีกว่าตอบผิด)
- [ ] ฆ่า Worker ระหว่างทำงาน แล้วงานถูก requeue (ไม่หาย ไม่ตอบซ้ำ)
- [ ] กู้ `pg_dump` จริงลงเครื่องทดสอบ แล้วข้อมูลครบ
