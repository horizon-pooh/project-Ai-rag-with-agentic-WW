> **สถานะ (22 ต.ค. 2026): แบบเก่า — แบบหลักอยู่ที่ `docs/Line_ai_bot.md` (ทั้งไฟล์)**
> ยังใช้ได้: หลักการข้อ 1, 3, 4 / รายการเอกสาร / แนวคิด shadow ก่อนเปิดจริง
> ล้าสมัย: Node.js/pm2, ตารางโฟลเดอร์ `src/`, แผน 4 สัปดาห์
> โครง Python ใหม่อยู่ที่ `app/` (stub ยังไม่มีโค้ด) — ไฟล์ JS ใน `src/` เป็นต้นฉบับแนวคิดแบบเก่า ไม่ลบ ไม่แก้

> `line_` ยังใช้งานได้เหมือนเดิม ไม่ได้แก้อะไรในนั้น

## ภาพใหญ่

เปิด `docs/diagrams/index.html` ในเบราว์เซอร์ จะเห็นไดอะแกรม 6 ภาพ (แบบหลัก ฉบับ 3):

1. ภาพรวมระบบบน server บริษัท
2. หนึ่งข้อความเดินผ่าน pipeline 9 ขั้น
3. สถานะ bot กับ human
4. ลำดับการเรียก AI API (call_ai)
5. ทางด่วนตอนลูกค้าขอพนักงานระหว่างรอ AI
6. โครงสร้างโค้ด `app/` เป็นชั้น

## หลักการ 4 ข้อ (มาจากการตรวจของสภาที่ปรึกษา — ดู `docs/decisions.md`)

1. **ส่งข้อความเข้า LINE ได้ทางเดียว** คือผ่าน `src/line/sendGuard.js` ซึ่งเช็ค state ล่าสุดก่อนส่งทุกครั้ง
2. **Softnix คือคอขวด ไม่ใช่ server** จึงต้องมีคิวที่จำกัดความยาว ยกเลิกได้ และบอกลูกค้าตามจริงว่าต้องรอนานเท่าไหร่
3. **ส่งต่อคนต้องมีคนรู้** — `src/notify/` ต้องเสร็จก่อนขึ้นระบบจริง
4. **ระบบล่มต้องไม่ทำให้ลูกค้าหาย** — `src/ops/killSwitch.js` ปล่อยให้ call center รับทั้งหมด

> **สถานะ (22 ต.ค.):** ข้อ 1 (sendGuard), 3 (แจ้ง call center), 4 (kill switch) ยังใช้ — ย้ายเข้าแบบใหม่
> ข้อ 2 "Softnix คือคอขวด" ขึ้นกับว่า AI API คือ Softnix หรือไม่ — **รอคำตอบ**

## โฟลเดอร์ (1 ประโยคต่อโฟลเดอร์)

> **แบบเก่า** — โครงใหม่อยู่ที่ `app/` ดู `filemap.md`

| โฟลเดอร์ | หน้าที่ |
|---|---|
| `src/config/` | ค่าตั้งค่าและ secret ทั้งหมด อ่านจาก env ที่จุดเดียว ขาดเมื่อไหร่หยุดทันที |
| `src/routes/` | ทางเข้า HTTP: `/webhook`, `/close`, `/health` |
| `src/middleware/` | ตรวจ signature ของ LINE |
| `src/pipeline/` | ตัดของซ้ำ, เรียงคิวต่อคน, ตอบ FAQ โดยไม่ใช้ AI |
| `src/conversation/` | state ของลูกค้าแต่ละคน และการตัดสินว่าข้อความไปทางไหน |
| `src/jobs/` | คิวงานไป Softnix (เก็บใน Redis ไม่หายตอน restart) |
| `src/ai/` | คุยกับ Softnix และแปลง markdown เป็นรายการสินค้า |
| `src/line/` | คุยกับ LINE — **ทุกข้อความขาออกผ่าน `sendGuard.js`** |
| `src/notify/` | แจ้ง call center ตอนส่งต่อ + รู้เวลาทำการ |
| `src/store/` | ที่เก็บข้อมูล: memory (dev) / Redis (production) |
| `src/ops/` | kill switch และรายงานรายวัน |
| `src/observability/` | log, ตัวเลข, ซ่อนข้อมูลส่วนตัว (PDPA) |
| `src/catalog/` | ว่างไว้ — ค้นสินค้าจาก catalog โดยตรง ถ้า Softnix รับไม่ไหว |
| `dev/` | debug routes + stub ใช้ตอน dev เท่านั้น |
| `test/` | เทสต์ (ย้ายของที่ผ่านแล้วจาก MVP มาก่อน) |
| `deploy/` | ติดตั้งบน server บริษัท: pm2 + Redis + HTTPS |
| `docs/` | การตัดสินใจ, คำถามที่ค้าง, คู่มือตอนระบบมีปัญหา, ไดอะแกรม |
